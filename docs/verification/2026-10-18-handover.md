# Account persistence and maintainer handover verification

## Implemented

- Server-owned, atomic household profiles without passwords/PINs.
- Encrypted Spotify credentials in the existing data volume, persisted expiry and refresh-token rotation, concurrent refresh serialization, transient backoff and reconnect-required handling.
- Server-bound OAuth state and durable account/profile linking before acknowledgement; standalone single-use confirmation receipt on the scanning phone.
- A server-flagged, typed-confirmation testing reset, data-generation propagation to updated displays, and clearing of local runtime data without an Undo path to deleted notifications.
- Maintained-source formatting across WebUI/scripts, C# projects and Qt C++; shared editor/format/line-ending configuration; removal of unused keypad/empty database scaffolding and misleading debug chatter.
- Corrected application READMEs, current deployment/storage documentation, and the maintainer handover entry point.

## Not verified / deployment cautions

- Browser tooling reported no available browsers, so new visual layouts, keyboard/focus behaviour and narrow-screen interaction were not exercised in a browser. The isolated fixture was updated for password-free selection and guarded test controls.
- A real scanning-phone Spotify consent and real provider refresh still need verification. The confirmed receipt route itself was tested through a real local HTTP server, including HTML encoding, no-store headers and single-use consumption.
- These source changes and rebuilt artifacts were not pushed or deployed as part of this handover pass. The Pi's existing data/configuration were not changed.
- The former server stored accounts/tokens in process memory. Plan its first upgrade before restarting it; old credentials are not magically migrated. New persistent accounts survive normal container recreation with the same volume and encryption keys.
- `HOMESYSTEM_ALLOW_DATA_RESET` defaults to disabled. The choice to enable it on the normal home deployment is still awaiting the user's preference; do not expose it publicly without access controls.
- Profiles are deliberately not authentication. Provider lifecycle/transport static state, network authorization, the desktop-agent transport scaffold, physical-device testing and production Android signing remain explicit boundaries in the maintainer guide.
- Existing Qt/Android tooling reports optional Vulkan-header, platform-import and SDK/Gradle deprecation warnings; builds succeeded. The APK remains debug-signed and was not installed on a device.
